# Secret Storage for `skelet`: TDD plan

## Goal

Add secure external storage for fields declared as `Field(secret=True)`. Secret
values must not be cached in the instance: ordinary assignment writes to the
selected secret storage, and ordinary attribute access reads from it unless a
source shadows the field.

The implementation must preserve the existing `Storage` and `Field` behavior
outside the new secret-field paths. Work is test-first: add a failing regression
test before every behavior change, then make the smallest implementation change
that satisfies it.

If an unexpected behavior of the pre-existing code is discovered, do not encode
it in tests automatically. Stop and decide explicitly whether it is intended.
All project commands must run through the repository's `venv`.

## Public contract

### Storage protocol and implementations

- Export `SecretStorageProtocol` with three keyring-compatible methods:
  `get(service_name, username)`, `set(service_name, username, password)`, and
  `delete(service_name, username)`.
- Validate custom storage objects structurally and validate method call
  signatures with `sigmatch`. Each method must support the positional and named
  calls made by `skelet`.
- Add a `pristan` slot with `entrypoint_group='skelet'`, `max=1`, and an empty
  body returning `[]`.
- Register the bundled keyring plugin directly on the slot. Because the bundled
  plugin is imported with the slot, it does not need a project entry point.
- Resolve the plugin through `secret_storages.one()`. Translate pristan's
  resolution errors into `SecretStorageUnavailableError`.
- Implement `KeyringSecretStorage` as a thin wrapper around
  `get_password`, `set_password`, and `delete_password`.
- Keyring deletion is idempotent only for recognized missing-secret errors.
  Unexpected keyring and backend errors propagate unchanged.
- Keep keyring conditional dependencies compatible with supported Python
  versions: `25.5.0` on Python 3.8 and `25.7.0` on Python 3.9+.

### Configuration and precedence

- Add `secret: bool = False` and `secret_storage=None` to `Field`.
- Add class-level `secret_storage=...` to `Storage.__init_subclass__`.
- Add instance-level `_secret_storage=...` to `Storage.__init__`.
- Select the first non-`None` storage in this order:
  1. instance `_secret_storage`
  2. field `secret_storage`
  3. class `secret_storage`
  4. the single registered pristan plugin
- `None` means that the current level does not override the next one. At class
  level, omitted or `None` storage preserves an inherited class storage.
- Accept either an object implementing `SecretStorageProtocol` or a raw
  `dict[str, dict[str, str]]`. Wrap raw dictionaries in `DictSecretStorage`.
- Validate a raw dictionary when accepted: the root must be a dict, service names
  and usernames must be strings, nested values must be dicts, and stored secrets
  must be strings.
- Keep raw dictionaries by reference. Protecting them from later external
  mutation is the caller's responsibility and must be documented.
- Raise `SecretStorageConfigurationError` for:
  - field storage supplied while `secret=False`
  - class storage on a resulting class without secret fields
  - instance storage on a class without secret fields
  - an invalid dictionary shape
  - a storage object with missing or incompatible methods
- Raise `SecretStorageUnavailableError` while creating an instance if any secret
  field has no effective storage.

### Secret keys and inheritance

- Use `service_name = f'skelet.{type(instance).__module__}.{type(instance).__name__}'`.
- Use the effective field alias as the username; without an explicit alias, use
  the field name.
- Reject duplicate effective aliases across all fields of a class, including an
  explicit alias colliding with another field's default alias.
- Same-class instances using the same selected storage share secrets. Different
  module/class-name pairs use different service names.
- Subclasses use their own service names while inheriting class-level storage.
- Re-evaluate storage validity, aliases, inherited fields, replaced descriptors,
  and secret-to-plain field overrides during subclass creation.

### Read, write, and delete behavior

- Secret assignment never stores the raw value in `instance.__values__`; it
  serializes the prepared value and calls storage `set()`.
- Every unshadowed read calls storage `get()` again. Do not cache stored secrets
  in memory.
- Read priority is:
  1. source-loaded value
  2. secret storage value
  3. per-instance cached `default_factory` value
  4. static default
  5. the existing undefined-value `ValueError`
- A source continues to shadow storage after runtime assignment. Assignment still
  writes the new value to storage.
- Storage `get() -> None` means that the secret is absent. An empty string is a
  stored value and must go through normal parsing.
- Compute a secret field's `default_factory` once during every instance creation,
  including when a source or stored secret currently wins. Cache that result only
  as a per-instance fallback.
- `del instance.field` calls storage `delete()` and does not call the action.
  Deletion is idempotent for bundled keyring storage and dict storage.
- `read_only=True` rejects secret assignment with the existing read-only error
  and rejects deletion with `ReadOnlySecretDeleteError`.
- Propagate backend exceptions from `get`, `set`, and `delete` unchanged.

### Preparation, parsing, and serialization

- Secret assignment follows the established conversion pipeline documented by
  `skelet`: initial type check and validation, conversion, repeated type check and
  validation, conflicts, action, post-action check, serialization, then `set()`.
- Failed type checks, conversion, validation, conflicts, action, post-action
  checks, or serialization must leave storage untouched.
- If an action mutates a mutable value, validate the resulting value before
  serialization and persistence.
- Parse stored strings with `simtypes.from_string`; do not add special Optional or
  JSON-null semantics in `skelet`.
- Supported scalar annotations are `str`, `int`, `float`, `bool`, `date`, and
  `datetime`.
- Support `list`, `tuple`, and `dict`, including parameterized containers whose
  item/value type is one of the supported scalar types. Dict keys must be strings.
- Do not support `Optional`, `Union`, nested collection annotations, or other
  typing constructs not officially supported for this path.
- Treat `Any` and a missing annotation like raw `str`. For example, stored
  `"abc"` retains its quote characters and stored `null` is the string `'null'`.
- Parameterized containers use JSON-compatible representations. Tuple values are
  stored as JSON arrays and reconstructed as tuples by `simtypes`.
- Reject non-finite secret floats and unsupported values in unparameterized
  containers according to the documented secret-field contract.

### Visibility and errors

- Change `hide` to `Optional[bool] = None`.
- Preserve explicit booleans. For all other values, normalize to `True` for a
  secret field and `False` for a regular field.
- Hidden secret `repr()` displays a mask without reading secret storage.
- A secret with `hide=False` is read for `repr()` and displays its effective raw
  value. If no effective value exists, propagate the undefined-value error.
- `asdict()` currently returns raw effective secret values, including hidden
  fields. Masking `asdict()` is outside this plan.
- Parsing/type errors produced by `skelet` must include the service name and
  secret key. Mask the offending value when `hide=True` and show it when
  `hide=False`.
- Do not include a hidden secret's raw value anywhere in a `skelet`-generated
  exception or serialized traceback. User validators, converters, actions, and
  storage backends remain responsible for their own exception text.

### Thread safety

- Run secret `set()` and `delete()` under the field mutex.
- Run secret `get()` under the field mutex when `read_lock=True`; preserve the
  existing unlocked-read behavior when it is false.
- Preserve conflict and `share_mutex_with` relationships, including transitive
  relationships, so all connected fields share one mutex.
- Run conflict checks and actions under the same field mutex as persistence.
- Always release locks after exceptions from storage, actions, validation, or
  serialization.

## Implementation outline

1. Add the protocol, dict adapter, keyring adapter, key construction,
   serialization helpers, and pristan registry under `skelet/secrets/`.
2. Add and export the new error types and public secret-storage symbols.
3. Extend `FieldDescriptor`, `Field`, and typing overloads with `secret`,
   `secret_storage`, and optional `hide`.
4. Normalize and validate field, class, and instance storages through the field
   descriptor's storage-normalization method.
5. Extend `Storage.__init_subclass__` with class storage inheritance and effective
   alias validation.
6. Extend `Storage.__init__` with instance storage, availability checks, source
   tracking, and per-instance secret fallback materialization.
7. Add secret branches to descriptor get, set, and delete while retaining the
   established regular-field path.
8. Update `repr()` and `asdict()` for the visibility behavior above.
9. Update README sections for secret fields, sources, type limits, precedence,
   deletion, sharing, dict mutation, exceptions, and `asdict()`.
10. Update runtime dependencies for `pristan` and conditional keyring versions.

## Detailed test matrix

### Protocol, plugin, and backends

- Verify a conforming storage can round-trip through `get`, `set`, and `delete`.
- Parameterize missing and incompatible `get`, `set`, and `delete` methods,
  including positional and keyword call compatibility.
- Verify non-string, non-`None` results from `get()` are rejected on read.
- Verify backend exceptions from each operation preserve identity and traceback.
- Monkeypatch keyring functions and assert exact service, username, and serialized
  secret arguments.
- Verify recognized missing-secret deletion is idempotent while unrelated keyring
  deletion errors propagate.
- Verify the slot metadata, the one-plugin limit, default bundled resolution,
  `secret_storages.one()` result handling, and translation of zero/multiple-plugin
  resolution failures.

### Storage selection and configuration

- Independently prove field-over-plugin, class-over-plugin,
  instance-over-field/class/plugin, and every `None` fallback.
- Exercise field, class, and instance misuse without combining class definition
  and instance creation in one `pytest.raises` block.
- Parameterize every invalid raw dictionary shape, including mixed valid and
  invalid branches.
- Verify raw dict round-trip, idempotent deletion, shared-by-reference behavior,
  and same-class sharing.

### Aliases, keys, classes, and inheritance

- Verify default and explicit usernames and exact service names.
- Reject duplicate explicit aliases and aliases colliding with another field name
  in either declaration order.
- Verify sharing between same-class instances, deletion visibility across those
  instances, and isolation between different classes.
- Cover parent/subclass service names, inherited and overridden class storage, a
  new child secret field, replacement of a field-level descriptor, and
  secret-to-plain shadowing that leaves no valid secret-field use.

### Reads, writes, deletion, and precedence

- Prove assignment writes serialized storage and not `__values__`.
- Make `get()` return changing values and prove repeated reads do not use a cache.
- Verify delete, double delete, delete followed by reassignment, and delete
  followed by every fallback or the undefined-value error.
- Verify read-only assignment and the dedicated read-only delete error.
- Verify deletion never invokes the action.
- Cover class, field, and instance sources. Prove they shadow reads while runtime
  assignment still updates storage and source-shadowed `asdict()` avoids storage.

### Defaults and factories

- Prove storage beats static default and factory fallback, while neither fallback
  writes to storage.
- Verify default/factory mutual exclusion remains unchanged.
- Count one factory invocation per instance at initialization, including a
  source-shadowed instance.
- Verify repeated reads and reads after deletion use the same cached factory
  value, and mutable factory results are isolated between instances.
- Verify factory exceptions occur during instance creation.

### Types and serialization

- Round-trip every supported scalar, parameterized container, tuple, and bare
  container representation.
- Verify `str`, `Any`, and missing annotations preserve raw text, including
  `'null'` and quoted strings.
- Verify an empty string is present for `str` and fails parsing rather than
  falling back for incompatible types.
- Reject unsupported annotations at class creation.
- Reject invalid serialized values, mismatched parsed values, invalid container
  members/keys, unsupported nested types, and non-finite numbers.
- Verify conversion output, not input, is serialized, and serialization failure
  occurs before `set()`.
- Compare representative secret parsing vectors with `simtypes.from_string` and
  the documented environment/CLI-compatible behavior.

### Actions, validation, and conflicts

- Verify a successful assignment action receives old value, new value, and the
  instance, including assignment through constructor kwargs.
- Record the complete established preparation/action/set order.
- Verify unchanged values retain the existing no-op action semantics.
- Parameterize type, validation, conversion, conflict, action, post-action, and
  serialization failures; assert `set()` was not called.
- Verify conflict callbacks see effective source/storage/fallback values.
- Verify mutable action changes are rechecked and only a valid final value is
  persisted.

### Visibility, exceptions, and conversion functions

- Cover default and explicit `hide` normalization for secret and regular fields.
- Use fail-on-access storage to prove hidden `repr()` does not fetch a secret.
- Verify visible `repr()` fetches and displays the effective value and propagates
  the undefined-value error when appropriate.
- Verify `asdict()` returns raw effective values and honors sources.
- Parameterize hidden and visible deserialization errors; assert service name,
  key, expected type, and correct masking behavior.
- Serialize full tracebacks and assert a hidden raw secret does not occur anywhere
  in the text.

### Locks and concurrency

- Use `LockTraceWrapper` to assert storage `set()` and `delete()` happen while the
  field mutex is held.
- Assert `get()` is locked with `read_lock=True` and unlocked with
  `read_lock=False`.
- Trace conflict checks and actions under the shared mutex.
- Exercise secret/secret and secret/plain conflict or `share_mutex_with`
  relationships, including transitive groups.
- Verify concurrent operations do not overlap inside protected storage calls and
  failed assignments are not observable as candidate values.
- For exceptions from `get`, `set`, and `delete`, perform a subsequent operation
  and prove the lock was released.

### Typing, exports, and documentation

- Add positive typing fixtures for secret fields and object/dict overrides.
- Add negative typing fixtures for statically invalid override values and dict
  shapes where expressible.
- Verify documented public symbols through normal import tests; keep error exports
  in the existing error-test module.
- Review README and `pyproject.toml` directly. Do not add tests that assert their
  text or metadata.
